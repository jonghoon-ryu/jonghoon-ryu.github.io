# v0.2-x86_64-c

<p class="subtitle">A screen console and a PS/2 keyboard</p>

## 1. Before: serial only (`v0.1`)

In `v0.1` all input and output go through the serial port (COM1). QEMU's terminal is the serial port, which is fine, but **the screen stays frozen on the loader's last lines**.
The shell runs only on the serial port (a real QEMU screenshot):

@@IMG xv6-tut-v01-qemu-screen.png v0.1 in QEMU: the shell is running, but only on the serial port@@

VirtualBox showed a black window, and the shell needed `socat` on the serial socket. A real PC without a serial port shows nothing at all.

The loader already passed the screen information (`bootinfo.fb_base`, `fb_width`, …) in `v0.1`. Nothing used it.

### 2.1 Drawing text on the screen (`fbcons.c`, `font.h` new)

UEFI's GOP (Graphics Output Protocol) exposes the screen's pixels as one block of memory, the **frame buffer**. One pixel = 4 bytes. Writing there is drawing on the screen.

@@FIG v02 fb@@

Characters come from `font.h`, the bitmap font [Spleen](https://github.com/fcambus/spleen) turned into C arrays, and are painted pixel by pixel:

@@FIG v02 glyph@@

@@CODE v0.2-x86_64-c | kernel/fbcons.c | ^drawchar\(int col | ^}@@

`fbconsputc()` takes one character and moves the cursor. It handles `\n`, `\r`, `\b` and `\t`, and calls `scroll()` when the screen is full. During a panic it takes no lock (the panic may have happened while the lock was held):

@@CODE v0.2-x86_64-c | kernel/fbcons.c | ^fbconsputc\(int c\) | ^}@@

A frame buffer above `PHYSTOP` (128 MB) must be mapped into the kernel page table separately (VirtualBox and many real PCs). In `vm.c`'s `kvmmake()`:

@@CODE v0.2-x86_64-c | kernel/vm.c | the screen's frame buffer, for fbcons.c | ^  }@@

`console.c` sends every character to **both** the screen and the serial port, **the screen first** (why: top right of the diagram above).

@@FIG v02 backspace@@

### 2.2 The PS/2 keyboard (`kbd.c`, `kbd.h` new; `trap.c`, `main.c`)

@@FIG v02 kbdflow@@

The keyboard driver comes from the old x86 xv6 (xv6-public). A keyboard sends **scan codes**, not characters: one when a key goes down (`a` = `0x1E`) and the same plus `0x80` when it comes up (`0x9E`).

@@CODE v0.2-x86_64-c | kernel/kbd.c | ^kbdgetc\(void\) | ^}@@

`shift` remembers Shift, Ctrl, Alt and Caps Lock as bits. A scan code becomes a character through one of four tables (`normalmap`, `shiftmap`, `ctlmap`, `ctlmap`).
One thing xv6-public doesn't have was added: the `KBS_AUX` check (drop mouse bytes), because UEFI may leave the PS/2 mouse enabled.

The keyboard interrupt (IRQ 1) arrives through the IOAPIC as vector 33. `devintr()` gets one more branch:

@@CODE v0.2-x86_64-c | kernel/trap.c | trapno == T_IRQ0 \+ IRQ_KBD | return 1;@@

`main()` calls `kbdinit()` and `ioapicenable(IRQ_KBD, 0)`.

### 2.3 A VirtualBox window (`vbox.sh`)

`make vbox` now opens a **window** by default instead of running headless: screen size 2560 × 1440 (`EfiGraphicsResolution`), serial output to the file `vbox/serial.log` instead of a socket.
A socket that nobody is connected to blocks the serial port and slows down the whole kernel; the file avoids that. The old way: `VBOXTYPE=headless make vbox`.

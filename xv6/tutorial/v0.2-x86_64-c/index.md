# v0.2-x86_64-c

<p class="subtitle">A screen console and a PS/2 keyboard</p>

| | |
|---|---|
| **Previous tag** | `v0.1-x86_64-c` |
| **This tag** | `v0.2-x86_64-c` (commit `7829294`), the tip of branch `main` |
| **In one line** | adds the **screen** (UEFI frame buffer) and a **PS/2 keyboard** to the serial-only I/O. The shell works right in a VirtualBox window |
| **Important** | every C++ step (`step-01` …) is **compared with this tag**: the screen and keyboard code exist only here |

```sh
git diff --stat v0.1-x86_64-c v0.2-x86_64-c -- . ':!docs'
git checkout v0.2-x86_64-c && make clean && make vbox      # type in the VirtualBox window
```

## 1. Before: serial only (`v0.1`)

In `v0.1` all input and output go through the serial port (COM1). QEMU's terminal is the serial port, which is fine, but **the screen stays frozen on the loader's last lines**.
The shell runs only on the serial port (a real QEMU screenshot):

![v0.1 in QEMU: the shell is running, but only on the serial port](/assets/image/xv6-tut-v01-qemu-screen.png)

VirtualBox showed a black window, and the shell needed `socat` on the serial socket. A real PC without a serial port shows nothing at all.

The loader already passed the screen information (`bootinfo.fb_base`, `fb_width`, …) in `v0.1`. Nothing used it.

```cpp
drawchar(int col, int row, int c)
{
  c &= 0x7f;
  for (int j = 0; j < cons.charh; j++) {
    uint *p = cons.fb + (row * cons.charh + j) * cons.stride + col * cons.charw;
    uint bits, top;
    if (cons.charw == 32) {
      bits = font32x64[c][j];
      top = 0x80000000;
    } else {
      bits = font16x32[c][j];
      top = 0x8000;
    }
    for (int i = 0; i < cons.charw; i++)
      p[i] = (bits & (top >> i)) ? FG : BG;
  }
}
```

`fbconsputc()` takes one character and moves the cursor. It handles `\n`, `\r`, `\b` and `\t`, and calls `scroll()` when the screen is full. During a panic it takes no lock (the panic may have happened while the lock was held):

[`kernel/fbcons.c:111–151`](https://github.com/jonghoon-ryu/xv6-x86_64/blob/v0.2-x86_64-c/kernel/fbcons.c#L111-L151) (tag `v0.2-x86_64-c`)

```cpp
fbconsputc(int c)
{
  if (cons.fb == 0)
    return;

  // printk() may be called during a panic with locks held;
  // don't risk waiting for this lock then.
  int locked = 0;
  if (!panicking) {
    acquire(&cons.lock);
    locked = 1;
  }

  cursor(BG);
  if (c == '\n') {
    cons.cx = 0;
    cons.cy++;
  } else if (c == '\r') {
    cons.cx = 0;
  } else if (c == '\b') {
    if (cons.cx > 0)
      cons.cx--;
  } else if (c == '\t') {
    cons.cx = (cons.cx + 8) & ~7;
  } else {
    drawchar(cons.cx, cons.cy, c);
    cons.cx++;
  }
  if (cons.cx >= cons.cols) {
    cons.cx = 0;
    cons.cy++;
  }
  if (cons.cy >= cons.rows) {
    scroll();
    cons.cy = cons.rows - 1;
  }
  cursor(FG);

  if (locked)
    release(&cons.lock);
}
```

The keyboard driver comes from the old x86 xv6 (xv6-public). A keyboard sends **scan codes**, not characters: one when a key goes down (`a` = `0x1E`) and the same plus `0x80` when it comes up (`0x9E`).

[`kernel/kbd.c:62–99`](https://github.com/jonghoon-ryu/xv6-x86_64/blob/v0.2-x86_64-c/kernel/kbd.c#L62-L99) (tag `v0.2-x86_64-c`)

```cpp
kbdgetc(void)
{
  static uint shift;
  static uchar *charcode[4] = {normalmap, shiftmap, ctlmap, ctlmap};
  uint st, data, c;

  st = inb(KBSTATP);
  if ((st & KBS_DIB) == 0)
    return -1;
  data = inb(KBDATAP);
  if (st & KBS_AUX)
    return 0; // a mouse byte, in case the mouse is still on

  if (data == 0xE0) {
    shift |= E0ESC;
    return 0;
  } else if (data & 0x80) {
    // Key released
    data = (shift & E0ESC ? data : data & 0x7F);
    shift &= ~(shiftcode[data] | E0ESC);
    return 0;
  } else if (shift & E0ESC) {
    // Last character was an E0 escape; or with 0x80
    data |= 0x80;
    shift &= ~E0ESC;
  }

  shift |= shiftcode[data];
  shift ^= togglecode[data];
  c = charcode[shift & (CTL | SHIFT)][data];
  if (shift & CAPSLOCK) {
    if ('a' <= c && c <= 'z')
      c += 'A' - 'a';
    else if ('A' <= c && c <= 'Z')
      c += 'a' - 'A';
  }
  return c;
}
```

`shift` remembers Shift, Ctrl, Alt and Caps Lock as bits. A scan code becomes a character through one of four tables (`normalmap`, `shiftmap`, `ctlmap`, `ctlmap`).
One thing xv6-public doesn't have was added: the `KBS_AUX` check (drop mouse bytes), because UEFI may leave the PS/2 mouse enabled.

### 2.3 A VirtualBox window (`vbox.sh`)

`make vbox` now opens a **window** by default instead of running headless: screen size 2560 × 1440 (`EfiGraphicsResolution`), serial output to the file `vbox/serial.log` instead of a socket.
A socket that nobody is connected to blocks the serial port and slows down the whole kernel; the file avoids that. The old way: `VBOXTYPE=headless make vbox`.

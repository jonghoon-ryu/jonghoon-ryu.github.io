# 부록 A. 읽기 요청 따라가기

튜토리얼 본문은 **쓰기**를 중심으로 걸었다(7단계의 out-of-place update). 이 부록은 같은 길을 **읽기**로 걷는다. 읽기는 page 를 새로 만들지 않아서 단순해 보이지만, 매핑을 얻는 과정과 캐시 · barrier 와 만나는 지점이 많다.


<div style="margin-top: 60px;"></div>

## 1. 직접 해 보기 — 20번 읽는 작은 workload

[부록 C](/ftl-visual-simulator/reference/mqsim-code-analysis/tutorial/appendix-debugging/)의 `tinyread.xml` 로 읽기만 20번 보냈다(작은 page 하나씩, 캐시 끔). 결과 파일에서 읽을 수 있는 숫자는 다음과 같다.

| 항목 | 값 | 뜻 |
|---|--:|---|
| `Request_Count` / `Read_Request_Count` | 20 / 20 | 읽기 20개 |
| `Issued_Flash_Read_CMD` | **40** | 사용자 data 읽기 20 + **매핑 읽기 20** |
| `Issued_Flash_Read_CMD_For_Mapping` | 20 | 요청마다 CMT miss → translation page 읽기 |
| `CMT_Misses_For_Read` | 20 | 읽기 transaction 의 miss |
| `CMT_Misses` (합계 칸) | **0** | ← 합계 칸은 아래 설명처럼 일부 miss 를 빠뜨린다 |
| `Device_Response_Time` | 179 µs | 매핑 읽기 약 75 + data 읽기 약 75 + 전송 약 30 |

**읽기 한 번에 flash 읽기가 두 번**이다. 데이터를 읽기 전에, 그 데이터가 어디 있는지 적힌 translation page 를 먼저 읽어야 하기 때문이다([translation page 깊이 보기](/ftl-visual-simulator/reference/mqsim-code-analysis/big-picture/translation-pages/)). 같은 workload 를 쓰기로 보내면 `Device_Response_Time` 이 854 µs(= 매핑 읽기 약 75 + 쓰기 program 약 750 + 전송)로, 읽기와 쓰기의 시간 차이가 거의 program 시간(tPROG)에서 나온다.

### CMT_Misses 합계 칸이 0 으로 나오는 이유

`query_cmt`(`:510`)를 보면 **miss 를 세는 위치가 둘**이다.

| 상황 | 세는 카운터 |
|---|---|
| CMT miss 인데 항목을 *바로* 만들 수 있다(처음 쓰는 translation page, 또는 쓰기 중인 항목에서 가져옴) | `CMT_miss` **와** `readTR_CMT_miss`/`writeTR_CMT_miss` |
| CMT miss 이고 translation page 를 **flash 에서 읽어야** 한다 | `readTR_CMT_miss`/`writeTR_CMT_miss` **만** |

그래서 위 실험처럼 모든 요청이 flash 읽기를 필요로 하면 합계 칸 `CMT_Misses` 는 0 인데 `…_For_Read` 는 20 이 된다. **miss 를 보려면 `CMT_Misses_For_Read/Write` 와 `Issued_Flash_Read_CMD_For_Mapping` 을 봐야 한다.** (`Total_CMT_Queries` 는 정상이다.)

## 5. 처음 읽는 주소 (unmapped read)

| | 원본 MQSim | 이 프로젝트 |
|---|---|---|
| 한 번도 쓰지 않은 LPA 를 읽으면 | `online_create_entry_for_reads` 가 가짜 매핑을 만들고 flash 를 **실제로 읽는다** | `Unmapped_Reads_Return_Zeros` 로 flash 를 건너뛰고 0 을 반환 |
| 시간 | 정상 tR 소비 | 거의 즉시 완료 |
| 위 실험(`Initial_Occupancy 0`)에서 | 읽기 20개 모두 flash 를 두 번씩 읽음 (40번) | — |

위 숫자(40번)는 **원본 빌드**에서 얻은 것이다. 원본은 "빈 SSD 에 읽기를 보내도 flash 가 읽힌다" 는 점이 시뮬레이션 결과를 부풀린다. 이 프로젝트가 그것을 바꾼 이유는 [쓰기 전에 읽으면](/ftl-visual-simulator/reference/mqsim-code-analysis/read-before-write/) 과 [튜닝된 코드](/ftl-visual-simulator/reference/code-change/tweaked-code/) 에 있다.

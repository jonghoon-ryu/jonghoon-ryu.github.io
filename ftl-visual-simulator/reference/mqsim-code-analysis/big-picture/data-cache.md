# 데이터 캐시 깊이 보기

[튜토리얼 5단계](/ftl-visual-simulator/reference/mqsim-code-analysis/tutorial/step5-cache/)에서는 쓰기 경로의 큰 줄기만 봤다. 여기서는 캐시가 **무엇을 어떻게 들고 있고, 읽기·쓰기가 어떻게 달라지며, 시간은 어떻게 모델링되는지**를 그림으로 정리한다. 코드는 `ssd/Data_Cache_Manager_Flash_Advanced.cpp`(584줄), `Data_Cache_Flash.*`, `Data_Cache_Manager_Base.*` 이다.


<div style="margin-top: 60px;"></div>

## 1. 캐시 모드 네 가지

`Caching_Mechanism` 이 구현(`SIMPLE` / `ADVANCED`)을, flow 별 `Device_Level_Data_Caching_Mode` 가 모드를 고른다.

| 모드 | 읽기 | 쓰기 |
|---|---|---|
| `TURNED_OFF` | 곧바로 FTL | 곧바로 FTL |
| `WRITE_CACHE` | 캐시에서 조회 후 없는 부분만 FTL | **destage 버퍼**로 받는다 (`write_to_destage_buffer`) |
| `READ_CACHE` | 캐시 조회 + 읽어 온 데이터를 캐시에 채움 | 곧바로 FTL |
| `WRITE_READ_CACHE` | 위 둘 다 | 위 둘 다 |

기본 샘플 설정은 `ADVANCED` + 256 MiB 이고 workload 의 flow 는 `WRITE_CACHE` 다.

세 가지를 기억하자.

1. **사용자 요청은 DRAM 쓰기가 끝나면 완료**된다. flash 쓰기가 끝나기를 기다리지 않는다.
2. **hot/cold 휴리스틱** — bloom filter 에 없는(처음 보는) LPA 는 cold 로 보고 곧바로 flash 로도 쓰고, 이미 본 LPA 는 DRAM 에 머물게 한다. bloom filter 는 시뮬레이션 시간으로 1초(`bloom_filter_reset_step` = 10⁹ ns)마다 비워진다. 이 때문에 같은 page 를 반복해서 쓰면 flash 쓰기가 크게 줄어든다.
3. **back-pressure** — 쫓겨나는 데이터와 flash 로 내려갈 데이터의 양(`back_pressure_buffer_depth`)이 한도를 넘으면 새 요청은 `waiting_user_requests_queue_for_dram_free_slot` 에서 기다린다. 캐시가 가득 차도 호스트에 무한히 응답하지는 않는다.

flash 쓰기가 끝나는 완료 신호(`handle_transaction_serviced_signal_from_PHY`)가 오면 캐시가 slot 을 정리한다: 그 사이 더 새로운 데이터로 덮이지 않았다면(타임스탬프 비교) slot 을 **제거**한다.

## 4. 읽기와 update read

- **READ_CACHE 계열**: flash 에서 읽어 온 page 는 `Insert_read_data` 로 캐시에 들어가고(필요하면 LRU evict), DRAM 쓰기 시간이 모델링된다.
- **update read**: FTL 이 page 의 일부만 덮는 쓰기를 위해 옛 데이터를 읽으면(`RelatedWrite != NULL`), 그 완료는 **캐시 매니저가 소비**한다. 쓰기 transaction 의 `RelatedRead` 를 비워서 TSU 가 이제 그 쓰기를 내려보낼 수 있게 한다([7단계](/ftl-visual-simulator/reference/mqsim-code-analysis/tutorial/step7-write-alloc/)의 partial write).

## 6. 이 프로젝트에서의 의미

- 시뮬레이터의 "DRAM 쓰기 캐시" 체크박스가 이 모드(`WRITE_CACHE` ↔ `TURNED_OFF`)다. 켜면 같은 page 에 대한 반복 쓰기를 DRAM 이 흡수해서, 호스트 요청 수백만 개에 flash 쓰기는 수백 개만 나간다.
- 캐시를 끄면 거의 모든 요청이 flash 쓰기가 되어 GC 가 훨씬 자주 일어난다.
- **TRIM 의 한계**: 이 프로젝트가 추가한 `Trim_lpa()` 는 FTL 의 매핑만 건드리고 **캐시 안에 남은 데이터는 건드리지 않는다**([Code Change](/ftl-visual-simulator/reference/code-change/upstream-diff/)).

# Preconditioning — 오래 쓴 SSD 로 시작하기

MQSim 은 원래 **성능을 재는** 시뮬레이터다. 새 SSD 에서 재면 GC 가 한참 동안 일어나지 않아 결과가 너무 좋게 나오므로, 측정 전에 SSD 를 "steady state" 로 만들어 두는 단계가 있다. 이 프로젝트는 쓰지 않지만 설정에 `Enabled_Preconditioning` 과 workload 의 `Initial_Occupancy_Percentage` 가 있어서 알아 둘 필요가 있다.

## 2. FTL 의 준비 (`FTL::Perform_precondition`, `FTL.cpp:47`)

1. **매핑 page 배치** — [translation page](/ftl-visual-simulator/reference/mqsim-code-analysis/big-picture/translation-pages/) 를 flash 에 둔다.
2. **요청 속도 추정** — 각 workload 의 도착 속도(큐 깊이 방식은 평균 지연으로 환산)를 합산한다.
3. **steady state 에서 접근되는 LPA 집합 만들기** — flow 의 통계(주소 분포 · 시드 · 읽기 비율 · working set)로 같은 난수를 돌려서, `Initial_Occupancy_Percentage × 논리 page 수` 개의 LPA 를 뽑는다. 핫/콜드 비율이 30% 를 넘으면 균등 분포로 취급하는 등의 단순화가 있다.
4. **block 별 valid page 분포 계산** — 아래 모형으로 "valid page 가 i 개인 block 의 비율" 을 구한다.
5. **물리 page 에 배정** (`Allocate_address_for_preconditioning`) — 먼저 LPA 를 plane 들에 나누고, 각 plane 안에서는 위 분포에 맞게 block 마다 valid page 개수를 정해 valid page 와 invalid page 를 채운다.
6. **캐시 데우기** — `Do_warmup()` 이 캐시 모드별로 분기하지만, 각 분기의 본문이 **비어 있어서 사실상 아무것도 하지 않는다**(`Data_Cache_Manager_Flash_Advanced.cpp`). 주석 수준의 계획만 남은 부분이다.

### 평균장 모델

```cpp
rho = Initial_occupancy_ratio × (1 − OP) / (1 − (GC 시작 전 최소 free page) / block_no_per_plane);   // FTL.cpp:434
```

`rho` 는 "GC 가 돌고 있는 정상 상태에서 block 이 평균적으로 얼마나 차 있는가" 이다. GC 정책별로 분포를 계산한다 — RGA 는 d-choices 모델(`Euler_estimation` 으로 수치 적분), GREEDY/FIFO 는 d 를 크게(30) 잡은 같은 모델로 근사, RANDOM/RANDOM_P 는 닫힌 식, 마지막으로 hot/cold 트래픽은 균등 분포 결과를 변형한다. 코드 주석이 인용하는 문헌은 B. Van Houdt 의 평균장 모델 논문(SIGMETRICS 2013, Performance Evaluation 2014)이다.

## 3. 이 프로젝트에서의 의미

- 시뮬레이터의 모든 프리셋은 `Enabled_Preconditioning = false` 로 시작해서 **빈 SSD 에서 출발**한다. workload 의 `Initial_Occupancy_Percentage` 는 읽히지만 쓰이지 않는다([원본의 알려진 한계](/ftl-visual-simulator/reference/mqsim-code-analysis/big-picture/known-limits/)).
- 쓴 적 없는 LPA 를 읽을 때 원본이 페이지를 예약하는 `online_create_entry_for_reads()` 는 preconditioning 을 생략했을 때를 위한 **지연(lazy) 버전**이다([쓰기 전에 읽으면 …](/ftl-visual-simulator/reference/mqsim-code-analysis/read-before-write/)).

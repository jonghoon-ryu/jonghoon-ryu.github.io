# 요청 하나가 지나가는 길

호스트가 보낸 요청 하나가 SSD 안에서 어떤 단계를 거치는지를 **그림 두 장**으로 본다. 각 단계의 코드는 튜토리얼에서 하나씩 열어본다.

- **캐시 적중이면 FTL 을 건드리지 않는다.** DRAM 읽기 시간만 모델링한다.
- **CMT 미스는 flash 읽기를 한 번 더 만든다.** 매핑 테이블 자체가 flash 에 저장돼 있어서, 매핑을 얻으려고 translation page 를 읽어야 한다. 그래서 같은 읽기가 CMT 에 따라 flash 접근 1번 또는 2번이 된다.
- **한 번도 쓴 적 없는 LPA 를 읽으면** 원본 MQSim 은 그 자리에서 물리 page 를 예약한다([쓰기 전에 읽으면 페이지가 소비되는 이유](/ftl-visual-simulator/reference/mqsim-code-analysis/read-before-write/)).

## 3. 쓰기와 읽기의 비대칭

| | 읽기 | 쓰기 |
|---|---|---|
| 물리 주소 | 매핑이 **이미 정해 둔** 곳 | FTL 이 **새로 정한** 곳 (out-of-place) |
| 매핑 테이블 | 읽기만 한다 | 갱신한다 (새 PPA 로) |
| block 상태 | 변화 없음 | 옛 page 는 invalid, 새 page 는 valid, write frontier 전진 |
| 부수 효과 | 없음 | write frontier 가 가득 차면 **GC 검사** — 여기서 GC 가 시작될 수 있다 |

GC 는 "쓰기가 많아서" 시작하는 게 아니라, **쓰던 block 이 가득 차서 빈 block 풀이 줄어들 때** 시작한다. 이 점은 [9단계](/ftl-visual-simulator/reference/mqsim-code-analysis/tutorial/step9-gc/)에서 코드로 확인한다.

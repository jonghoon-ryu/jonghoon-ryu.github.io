## MQSim 은 어떤 프로그램인가

MQSim 은 SSD 의 내부(호스트 인터페이스, DRAM 캐시, FTL, 플래시 칩)를 **소프트웨어로 흉내 내는 시뮬레이터**다. 실제 SSD 없이 "이 설정이면 GC 가 얼마나 일어나고, WAF 와 지연은 어떻게 될까" 를 계산한다. 이 시뮬레이터는 이 C++ 코드를 그대로 WASM 으로 컴파일해서 브라우저에서 돌린다.

2. **FTL 은 부품 네 개의 묶음이다.** 주소 매핑(AMU) · 블록 매니저 · GC/WL · 스케줄러(TSU) 가 일을 나눠 한다.
3. **시간은 이산 이벤트 엔진이 만든다.** 아래에서 설명한다.

### 이산 이벤트 엔진 — 시간을 흘려보내지 않고 건너뛴다

MQSim 은 시계를 1 ns 씩 똑딱이며 돌리지 않는다. **알람 목록**(언제, 누구에게, 무슨 일이 일어나는지)을 들고, 가장 이른 알람을 꺼내 시계를 그 시각으로 **점프**시키고, 알람을 받은 부품이 반응하게 한다. 시간이 걸리는 일(PCIe 전송, flash 읽기 75 µs, 쓰기 750 µs, 지우기 3.8 ms)은 그 시간을 기다리는 대신 **"지금 + 걸리는 시간" 에 새 알람을 걸어 두는 것**으로 표현한다.

## FTL Visual Simulator : 계획과 실제

1. GitHub 에 있는 다양한 open source 중에서 MQSim 선정 ( [선정 이유](/ftl-visual-simulator/reference/mqsim/#결론--왜-mqsim-인가) )
2. 지난 번 app 으로 만들었을 때의 문제점
    - 사람들이 앱 설치를 귀찮아 함
    - 앱을 믿지 않음 ( 보안 등 )
    - 그러나 웹에서 실행하도록 하면 안전함 ( sandbox )
3. 웹에서 해당 open source 를 눈으로 볼 수 있도록 visual simulator 를 만듦 ( 거의 대부분 Claude 가 함 )
4. 동작시켜 보고 Claude 에게 수정하도록 하는 일을 반복하여 기본 기능 완성
5. 원래 코드에 없던 내용 추가 ( [원본 대비 변경 사항](/ftl-visual-simulator/reference/code-change/upstream-diff/), [Code Change](/ftl-visual-simulator/reference/code-change/) )
    - 새 기능 : Cost-Benefit GC, TRIM, `Unmapped_Reads_Return_Zeros` — [6절](/ftl-visual-simulator/reference/code-change/upstream-diff/)
    - 시뮬레이터를 위한 변경 — [7절](/ftl-visual-simulator/reference/code-change/upstream-diff/)
    - 화면에 다 보이도록 block 수를 줄인 데모 규모 튜닝 — [튜닝된 코드](/ftl-visual-simulator/reference/code-change/tweaked-code/)
    - 이 과정에서 원본의 버그 31개도 발견해서 수정 — [버그 목록](/ftl-visual-simulator/reference/code-change/bug-list/)

### 10/11 이후 (~10/23)

1차 마감(10/11) 뒤에는 새 기능보다 **직접 써 보며 걸리는 곳을 고치는 일**이 이어졌다. 자세한 목록은 [개발 계획 — 10/5~10/16](/ftl-visual-simulator/plan/).

- **10/11** — 앱 커밋 19개. 기본값을 OP 20% · GC 임계값 30% · 읽기 30% 로 바꾸고, ▶ 를 로그 한 줄 단위로 천천히 재생하게 했다. DRAM 캐시를 32 page 로 줄여 flash 변화가 몰려 보이던 문제를 없앴고, 엔진 버그(재실행 결과가 달라짐, TRIM 이 캐시를 무시함, OP 0% 에서 쓰기가 멈춤)를 고쳤다.
- **10/16** — **한 줄 되돌리기(⏪)** 추가. 엔진 메모리 스냅샷으로 바로 앞 상태를 정확히 복원한다 ([Step-back](/ftl-visual-simulator/reference/step-back/)). 재생 버튼 이름도 정리했다.
- **10/23** — [개발 계획](/ftl-visual-simulator/plan/) 의 체크리스트를 실제 진행에 맞게 표시했다. Claude 가 할 일 가운데 남은 것은 설계 문서 · 와이어프레임(만들지 않음)과 선택 항목인 trace 파일 업로드뿐이다.
- 아직 못 한 가장 큰 것은 그대로 **Hybrid(log-block) 매핑**이다.

## 소회

- 처음에는 코드 분석과 구현을 동시에 진행하려고 했었다.
- 그러나 하다 보니 구현을 먼저 하게 되었다.
- 구현을 먼저 한 이유 중 하나는 Claude 가 처음에 좀 자신 없는 듯한 말투로 "어떤 어떤 위험이 있다" 라고 해서, 일단 되는지부터 해 본 것이다.
- 구현하면서, 그리고 동작시키면서 문제점을 수정해 나가다 보니 코드는 수박 겉핥기로만 알고, 실제로 나는 Claude 가 구현한 것을 동작시켜 보는 오퍼레이터가 되어 있었다.
- MQSim 이라는 원본 코드가 FTL 의 일부만을 구현한 코드다 보니, 원본을 변환한 Visual Simulator 또한 한계가 있다.
